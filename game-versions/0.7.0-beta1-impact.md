## Project-by-project preparation

### TFM2 Dynasties — CRITICAL priority after stable release
- Keep universal person-to-person affinity, event modifiers and dynastic lineage as independently modeled concepts; **do not conflate them** with team-to-manager trust, team atmosphere, club rivalry heat, player reputation tier or manager reputation score.
- Prototype **read-only probes** for player/team/manager IDs, Messenger author and target, message type, promise/decision, deadlines, trust, team atmosphere, Ego, captain, status and club transitions.
- Evaluate relationships after changing clubs, retirement/death, player departure, no eligible five-player lineup, manager firing, and native auto-recruitment. Check whether new manager-career behavior changes game-over/forfeit design; do not presume it fixes the previously identified base-game roster auto-repair problem.
- Decide precedence between native morale/stress/loyalty updates and Dynasty interpersonal events so negative modifiers do not apply twice. Keep native team rivalry separate from personally motivated grudges.
- Test weekly calendar ordering, save/load persistence, offline/retired entities, multiplayer differences, and whether Academy/All-Star/Hall-of-Fame events create temporary participant records.

### Flame Simulator — CRITICAL priority after stable release
- **Ego >=70** strongly supports contextual teammate blame after defeats; **Ego >=60** supports advice resistance. These thresholds are advertised for Messenger, not currently proven as public SDK fields.
- Use Ego, reputation tier, captain status, streak, prior arguments, trust/atmosphere, team rivalry, post-loss self-blame and recent results as candidate **context inputs**, not automatic commands to inject chat.
- Separate native squad Messenger chat from existing Flame goals (in-match team/all chat and Tribunal-based phrase corpus). A native squad chat thread is not proof that in-match chat channels/events exist or should be replaced.
- Probe how player ID maps to Ego/personality, whether native group messages are de-duplicated, and whether a mod can observe event context without scraping strings. Re-run 0.6.3 ABI 9 / F7 profile verification and trait mapping; check newly added jungle-invasion trait rather than assuming prior array size.
- Respect user-controlled enable/disable options and avoid doubling native blame messages. Changes to tone/branching require explicit empirical behavior tests.

### Minion Champs / Creep Chaos — HIGH for new champion pool, MEDIUM for engine
- Add new champions only after range, melee/ranged, target validation, lane pathing, teleport/transport, CC and replay tests. Initial policy remains **vanilla-only curated lanes**, stronger disruptive kits for specialized jungle/bosses, not indiscriminate pool expansion.
- Gladiator's duel, Ferryman's carried untargetable ally, Bombardier's stationary deploy, Hypnotist's Sleep, and new invade-jungle player trait are high-risk cases. Sleep/wake and duel interactions require target-class probes, including MCs treated as champion targets.
- Preserve current 0.6.3 working profiles. Re-scan native hooks and behavior before any 0.7.x run; no address portability inferred.
- Probe main-menu/simulation shortcuts only after validating that selected structures really belong to the same authoritative match context.

### Harbinger Direct Control — HIGH compatibility test
- New champion skills may require targeting, channel interruption, immobility, duel enforcement, ally transport, cleanse/immunity and replay synchronization rules.
- Revalidate Ctrl+Home/End, F1–F10, Q/W/R, RMB attack/move, MMB camera, old/new UI layouts, rewind disabling and restored controls. The new Help default I is a possible binding conflict only if a mod uses that key.
- Replay/presentation synchronization, hooked addresses, binary signatures, SDK ABI, remote input, multiplayer compatibility remain **unproven**. Retain fail-closed profile matching and avoid merging functional changes without authorization.

### Berserker Keeps Yelling — LOW direct feature risk
- No advertised Berserker rage changes. Retest rage start/end/interruption/death, audio overlap, replay event ordering and 0.7.x SDK integration. New match types and replay architecture changes are unknown; no claim of compatibility.

### Other multiplayer / shared infrastructure
- Manager career is **single-player only**. Do not design multiplayer Dynasties around career transfer/firing until verified.
- Native new UI, event schedules, and career states may alter workflow screens but do not establish network authority or available remote input; maintain the $0 recurring hosting constraint independently.
- New in-game Help and player data paths are potentially useful observability surfaces, **not established API contracts**.
