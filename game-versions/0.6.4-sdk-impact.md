# Teamfight Manager 2 0.6.4 — stable SDK ABI 10 and project impact

**Assessment date:** 2026-10-14. **Evidence:** static inspection of the user's original uploaded 0.6.4 Windows executable and `mod-sdk-stable.zip`, comparison of shipped `contract/abi_v1.txt` with `contract/frozen/abi_level_9.txt`, and the developer's [0.6.4 API reference](https://github.com/teamsamoyed/TeamfightManager2Mod/blob/main/docs/stable-api-reference.md#added-in-064) ([documentation commit](https://github.com/teamsamoyed/TeamfightManager2Mod/commit/064c2facbd725c71a4d1fae17f4dc75c1f1ea7a0)). **Classification: SDK contract / official documentation / original-EXE static fingerprint; NOT mod runtime verification.**

## Pinned inputs and compatibility

- Shipped SDK `base_version.txt`: `0.6.4`; `contract/abi_v1.txt`: **ABI level 10**. The frozen preceding contract is **ABI level 9**, used by the 0.6.3 project probes.
- Uploaded `TeamfightManager2.exe`: **SHA-256 `a1d05045405a12e2bed182daeafcad8c8a40cf29ab68ba6ea5bfd30257439582`**; PE timestamp **`0x6ACF3112`**; PE SizeOfImage **`0x0533F000`**; x64 image base `0x140000000`; disk length **87,228,416 bytes**. These are exact properties of the supplied file, not proof of any native-hook address or gameplay behavior.
- SDK archive SHA-256 `8bc5b77d0ab4899e8842b4a70dac198b2cf8a6a030ddc69e755e445fe42a1d5d`. The shipped SDK and executable were independently inspected; **no full binary diff against the original 0.6.3 executable and no game launch were performed**.
- The developer defines the stable API as *append-only*: newly built mods still load on older stable-API hosts, and unsupported newer methods return graceful failure; older compiled stable modules can continue to load on 0.6.4. This is an **API/loader compatibility promise**, not validation of a particular mod's runtime logic or native hooks. **Do not raise `declare_stable_mod!(init, requires = 10)` automatically.** Opt in only if that mod is unusable on older hosts without the new calls; see [stable-native-mods compatibility](https://github.com/teamsamoyed/TeamfightManager2Mod/blob/main/docs/stable-native-mods.md#compatibility-across-game-updates).
- Stable ABI does **not** freeze native Rust/C++ code addresses, entity layouts outside the SDK, proprietary replay internals, detours, UI ownership or simulation semantics. **All 0.6.3 RVA/address profiles remain unverified and must fail closed on 0.6.4.**

## ABI 9 → 10: actual shipped additions

The comparison below is specifically from the bundled ABI contract; behavior notes are sourced to the linked developer reference. Old fields are retained; new vtable fields are appended.

| Area | ABI 10 addition | Exact limitation / likely use |
| --- | --- | --- |
| Entity classification | `StableEntity::kind() -> Option<EntityKindV1>`; `Champion`, `Minion`, `Jungle`, `Epic`, `Serpen`, `Tower`, `Nexus`, `Summon` | Distinguishes *actual simulation entity types*, not a model/sprite swap and not a way to promote a minion to champion dispatch. |
| Cooldown/charges | `StableEntity::cooldown(SkillSlotV1)`, `StableSim::entity_reduce_cooldown(id, slot, ticks)`; slots `Attack`, `Skill`, `Skill2`, `Ult`; new `CooldownV1` | **Champions only**. Exposes remaining ticks, full cooldown, max/available charges, time to next charge and unlock state. Reduction affects one slot, with charge refill semantics. This does **not** create cooldown slots or additional actions for lane minions. |
| Action AI | `StableAction::can_activate(sim, caster)`, `target_constraint(sim, caster, target)` | Deterministic, read-only **AI decision gates** applied across AI skill decisions. They do **not** block an input issued by custom `StablePlayerAi`; enforce hard gameplay restrictions again in the effect. |
| Action movement | `StableAction::can_use_with_move_by(&StableEntityView)` | Per-cast read-only caster state, falling back to old `can_use_with_move()`; not a control/remote-input API. |
| Effect range | `StableEffectType::may_adjust_range()`, `range_adjust(caster, target)` | `u64` additional world-unit range per pair; AI and engine checks honor it, **only adds range**. Requires `may_adjust_range=true`. |
| Read-only callback view | `StableEntityView` and its new vtable | Provides ID, team, level, kind, HP, stats, position, shield, buffs and CC; **valid only for the callback duration**, not a retained native entity pointer. |
| Passive kills | `StablePassive::on_unit_kill(sim, player, entity, victim)` | Awarded minion/jungle CS; distinguish by victim `kind()`. Champion deaths remain `on_kill`; Epic and Serpen team rewards do not fire this callback. |
| Draft/lineups | `DraftPhaseV1::Position`; `StableDraftHook::decide_positions`; `DraftCtxV1` adds both lineups' athlete IDs, team IDs, and slot lanes | Positions override **AI lane assignment after picks**, not live match input. Output must be a complete permutation of picked-champion indices or is ignored. Draft hook has no athlete record lookup itself; prefetch/store in a server hook if needed. |
| Save balance patching | `SettingTargetV1::AutoPatch` | Server read/write of per-save auto-patch configuration, effective at **next generated patch**, not immediately in a running match. Client reads fail. |
| Replay athlete data | Added `exp`, `cs`, `cs_jungle`, `self_heal` to replay athlete records | Recorded match data: result screen CS = `cs + cs_jungle`. Old replays read **zero**, not historically reconstructed values. |

**Host-side behavior changes affecting already-compiled stable mods (developer-documented, not independently exercised):**
1. Passive callbacks now receive the match-view frame, so passive-spawned projectiles and passive healing/gold numbers can be represented in the watched view. This is **not** a new authoritative replay timestamp or a guarantee that custom SFX plays.
2. `cooltime_use_count = 0` is normalized to `1` rather than dividing by zero/crashing.

**Contract-shape audit:** `ActionVtableV1` 96→120 bytes, `EffectTypeVtableV1` 112→128, `PassiveVtableV1` 104→112, `SimVtableV1` 696→720, `DraftCtxV1` 120→184, `DraftHookVtableV1` 64→72. The added `CooldownV1` and `EntityViewV1` families and new enum codes are at the end of the shipped contract. Size changes reflect **append-only extension under the stable ABI**, *not* permission for a mod to interpret previous native memory offsets by the new struct sizes.

## Impact assessment by existing project

| Project | Practical opportunity | Not solved / migration gate |
| --- | --- | --- |
| **Creep Chaos / Minion Champs** | `kind()` can classify target/victim and differentiate lane minions from jungle bosses; champion-targeting mods can inspect a real entity type rather than inferring from presentation. AI gates and dynamic range may help **future genuinely registered custom champion actions**. | **High interest, but not a breakthrough for MC-owned abilities.** The new cooldown API is **champion-only**; nothing in the new contract installs B/C/D actions into native minion entities, changes kind-3 skill-state dispatch, makes visuals into champion identity, or proves authoritative replay-safe ability ownership. Preserve 0.6.3 native research as build-specific; repeat controlled visual/spawn/action tests on 0.6.4 before porting any detours. |
| **Dynasties** | Athlete IDs/team IDs exposed during the draft, with overrideable AI position assignments; richer match replay athlete records support career history, experience, CS and healing; `AutoPatch` opens save-level balance-policy work. Kill-credit callbacks can contribute to future relationship/trait experiments. | Draft IDs are not proof of cross-season stable identities or family/persistence support. No direct relationship/reputation/Ego events or marriage APIs are established by these ABI additions. Roster depletion, retirement, save reloads and 0.7.0-beta features remain separately untested. |
| **Flame Simulator** | New CS/jungle-CS and self-heal replay fields may support scoring/attribution; new unit-kill passive callback and typed entity kinds support future deterministic event sources if Flame later owns such callbacks. | No documented native-chat insertion API, semantic native chat line dispatcher, presented replay-frame clock, or guaranteed UI persistence fix. Existing 0.6.3 synthetic owned-row results must be rechecked separately. |
| **Berserker Keeps Yelling** | Passive frame fix may help **only if** the mod uses gameplay passives to emit supported frame visuals; additional entity kinds and cooldown reads could aid diagnostics when the controlled actor is a champion. | No direct Rage start/stop/death-during-Rage event and **no precise audio playback cursor** in the new SDK. `play_sfx` still needs a client-bound named view effect; existing observed WinMM WAV / projected-HUD scheduling remains separate. 0.6.3 native hook addresses and audio timings require revalidation on 0.6.4. |
| **Harbinger Direct Control / multiplayer research** | More flexible AI skill gates, per-cast movement capability, and actual per-champion cooldowns may assist a future stable-API-compatible skill controller. Draft position override is strictly prematch AI lineup policy. | No promise of authoritative external player-input injection, replay rewinding/control, camera ownership, multiplayer peer synchronization, or deterministic network transport. Existing 0.6.2/0.6.3 native profiles cannot be reused blindly. |

**Cross-project rule:** A new stable function's *presence in the SDK* is not proof it is called at the right simulation origin, makes a watched replay authoritative, persists through reload, or functions for non-champion entities. Keep per-project baseline and probe conclusions independent.

## Smallest useful migration/test checklist

1. **Baseline:** save the exact current working 0.6.3 game/SDK/mod build and probe result in the originating project before testing 0.6.4; use only compatible backups where allowed.
2. **Identity + loader:** compare executable SHA/PE metadata to the fingerprint above; log game, SDK ABI, host ABI and mod version. Stable-only load/smoke test first. A native detour with a 0.6.3 fingerprint must reject 0.6.4 until rediscovered.
3. **Feature-gated tests:** exercise `kind()` on one actual lane minion and one jungle unit; `cooldown()` on a champion and the **expected unavailable** minion case. Test casts/AI gates/charged cooldowns only on intentionally instrumented units, and replay consistency across origins if simulation mutation is involved.
4. **Presentation:** test pause, 1× and accelerated replay, seek, scene exit, audio cleanup, chat row ownership and frame-only VFX independently of deterministic simulation ticks. No need to watch a full-length match when a short bounded feature test suffices.
5. **Career:** verify `decide_positions` only at a Position phase, validate returned permutation and actual lane placement, check athlete/team ID mapping across saves and transitions, and compare new versus legacy replay record fields.
6. **No unconditional ABI floor:** keep the mod's `requires` permissive unless its **essential** functionality is impossible on an earlier supported host. Degrade gracefully when a 0.6.4 method is unavailable.
7. **Evidence labels:** only promote entries from *SDK documented/static* to *runtime verified* after game execution with observable effects and versioned logs; leave untested work as such.
