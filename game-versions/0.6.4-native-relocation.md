# TFM2 0.6.4 — independently relocated native entry points

**Assessment:** 2026-10-14. **Status:** **static binary verified** against the original user-supplied Windows x64 game executable. **Creep Chaos has physically runtime-verified Candidate A plus the relocated resource/animation entry trampolines in read-only mode on 0.6.4; Candidate B/C remain static-only, while the private presentation layouts are now static-revalidated for guarded runtime testing but not yet physically verified.** This file intentionally supersedes the migration blockers that merely said “the new native hooks have not been located.” The mappings below were derived **directly from the 0.6.4 executable**, independently of any confidential third-party material.

**Current target baseline is 0.6.4.** Version 0.6.3 remains historical evidence, not the desired default development target. Mods must update their build guards and their own native code to the new profile before in-game testing, rather than quietly running or probing the obsolete game.

## Practical migration requirements

1. Update each relevant project's accepted **0.6.4 SHA/PE profile**, hook RVAs and semantic guards. Do **not** reuse the 0.6.3 RVA under a changed version label, or disable safety checks just to make loading succeed.
2. For Harbinger and Creep Chaos, the five directly mapped entry points above **no longer need a new EXE upload or a fresh relocation investigation**. A compact bounded game smoke test remains to validate behavior.
3. Other hooks are **not implicitly relocated**. In particular, the Harbinger **camera-handler RVA/object layout and direct-input path** were *not established* by these checks; earlier 0.6.2 camera offsets are unsafe to transplant. Additional latest Creep Chaos probe-specific presentation/detour anchors not listed here also need their own scan. For those, prefer a local read-only extractor and small sanitized report rather than demanding the user upload the same executable repeatedly.

   **Creep Chaos scope clarification (source audit, not 0.6.4 runtime evidence):** relocating the resource/animation *entry points* does not by itself validate every private layout displacement used by later Creep Chaos probes. Before restoring role/per-slot mutation on 0.6.4, separately revalidate the resolver owned-string output layout formerly treated as capacity/data/length at `+0x00/+0x08/+0x10`, resource-view name fields `+0x58/+0x60`, animation-view type fields `+0x40/+0x48`, current-action fields `+0x70/+0x78`, and the primary-renderer coordinate pair formerly read at `+0x17C`. Probe 014G also needs the exact 0.6.4 primary resource-caller return site; the older Probe 013F/013M producer/owner inventories are diagnostic history rather than automatic gameplay dependencies. The Creep Chaos project now includes a bounded exact-SHA local scanner (`scripts/probe064-presentation-layout.py`) intended to produce a small sanitized JSON for these remaining relocations without re-uploading the executable. **No result from that scanner has been physically supplied or promoted yet.**
4. SDK-only mods (and portions of Flame, Berserker and Dynasties that use only stable APIs) can adopt SDK **ABI 10** without pretending they need native address relocation. Check 0.6.4 host initialization, scene and record availability as appropriate.
5. Treat this as the **0.6.4 development target now**, while keeping previous 0.6.3 evidence archived and reversible. Do not require a 10–20 minute full match when a short deterministic/test-view sample will establish the specific hook's correctness.

**Reproducibility evidence:** exact original file SHA and PE metadata above, `.pdata` function-start checks for five relocated entries, equal simulation strides, two common direct-call destinations, unchanged original function-entry byte signatures and branch-relative offsets, verified expected full asset literal. The original relocation study itself was static; the later Creep Chaos v0.0.35 runtime adoption below is separate user-executed physical evidence.

## Creep Chaos runtime adoption (2026-10-14)

**PHYSICAL RUNTIME, exact original 0.6.4 / stable ABI10; private raw log retained outside the KB.** Creep Chaos **v0.0.35** installed the relocated Candidate-A detour at `0x00C526A0` and the relocated world-resource / animation-key detours at `0x02AAB520` / `0x02AB4400`.

Candidate A is now physically revalidated for the specific role Creep Chaos needs: its stable observer only executes while the Candidate-A detour is active on the same worker thread and the stable simulation origin is `ClientMatchView`; the run produced one continuous watched-copy match/lifecycle stream through at least tick **38,229**. This confirms **Candidate A's live intersection with the watched ClientMatchView callback stream on 0.6.4**. It does not prove Candidate A is globally unique, and Candidate B/C remain static structural relocations only.

Both relocated presentation detours emitted their one-shot runtime marker **after the original function returned**, with `private_view_fields_read=false mutation=false`. Their total call counters continued increasing throughout the run. This physically validates the two **entry/trampoline/original-call paths**, not the old private entity/output layouts or the minion-specific substitution itself.

The same run incidentally revalidated Creep Chaos's simulation-side native lane schedule: **882 lane-minion slot observations = 49 complete 2-melee/1-ranged conceptual waves across all three lanes and both teams**, **0 sequence violations**, and **441/441 blue/red mirrored conceptual keys matching**. This is simulation-side evidence only; renderer↔StableEntity identity remains unproven.

**Historical boundary from the v0.0.35 runtime pass:** the entry smoke alone did not authorize role/per-slot artwork. That required the separate bounded `tfm2-064-presentation-layout.json` review. **That report has now been supplied and reviewed in the static-layout section above**, so role-only guarded runtime testing may proceed; per-slot selection remains disabled until the primary/+0x17C runtime check passes.

Originating sanitized detail: Creep Chaos `docs/TFM2-0.6.4-V0.0.35-RUNTIME-FINDINGS.md`.
