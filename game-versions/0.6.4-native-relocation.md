# TFM2 0.6.4 — independently relocated native entry points

**Assessment:** 2026-10-14. **Status:** **static binary verified** against the original user-supplied Windows x64 game executable; **runtime detour installation and gameplay behavior NOT YET VERIFIED**. This file intentionally supersedes the migration blockers that merely said “the new native hooks have not been located.” The mappings below were derived **directly from the 0.6.4 executable**, independently of any confidential third-party material.

**Current target baseline is 0.6.4.** Version 0.6.3 remains historical evidence, not the desired default development target. Mods must update their build guards and their own native code to the new profile before in-game testing, rather than quietly running or probing the obsolete game.

## Shared local verification — no new upload required

Run the committed [read-only standard-library verifier](../scripts/verify_tfm2_064_native.py) against the **locally installed** original 0.6.4 game executable. The verifier was executed on the uploaded 0.6.4 executable and **all** fingerprint, `.pdata`, prologue, semantic-branch, string-literal and shared-call checks passed. It **never patches the game or installs detours**.

From a checkout of the knowledge-base repository (example, PowerShell):

```powershell
python .\scripts\verify_tfm2_064_native.py "C:\Program Files (x86)\Steam\steamapps\common\Teamfight Manager2\TeamfightManager2.exe"
```

This handles source verification without uploading the proprietary binary to any other chat. A short text report can be preserved in the mod repository. **It is still mandatory to test new detours physically**, including their expected entity origin, logging, pause/replay lifecycle and unwind/trampoline behavior; a static PASS does not imply a live PASS.

## Practical migration requirements

1. Update each relevant project's accepted **0.6.4 SHA/PE profile**, hook RVAs and semantic guards. Do **not** reuse the 0.6.3 RVA under a changed version label, or disable safety checks just to make loading succeed.
2. For Harbinger and Creep Chaos, the five directly mapped entry points above **no longer need a new EXE upload or a fresh relocation investigation**. A compact bounded game smoke test remains to validate behavior.
3. Other hooks are **not implicitly relocated**. In particular, the Harbinger **camera-handler RVA/object layout and direct-input path** were *not established* by these checks; earlier 0.6.2 camera offsets are unsafe to transplant. Additional latest Creep Chaos probe-specific presentation/detour anchors not listed here also need their own scan. For those, prefer a local read-only extractor and small sanitized report rather than demanding the user upload the same executable repeatedly.
4. SDK-only mods (and portions of Flame, Berserker and Dynasties that use only stable APIs) can adopt SDK **ABI 10** without pretending they need native address relocation. Check 0.6.4 host initialization, scene and record availability as appropriate.
5. Treat this as the **0.6.4 development target now**, while keeping previous 0.6.3 evidence archived and reversible. Do not require a 10–20 minute full match when a short deterministic/test-view sample will establish the specific hook's correctness.

**Reproducibility evidence:** exact original file SHA and PE metadata above, `.pdata` function-start checks for five relocated entries, equal simulation strides, two common direct-call destinations, unchanged original function-entry byte signatures and branch-relative offsets, verified expected full asset literal. **No 0.6.4 mod module was installed or run as part of this static study.**
