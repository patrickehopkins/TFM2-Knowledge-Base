# High-value open investigations

These are **questions or test plans**, not completed discoveries.

1. **Exact playback event timing:** Berserker 0.6.3 Probes 005/006 did not show a subsecond cursor in tested stable SDK UI. Static Probe **009A** identified three unverified `game_time` LEA-shaped byte references in the exact SHA-256 `f21cf691799a83d9afa0ccae3e2b95862f5780446a501ee97860b91b752dbe2f` build (PE timestamp `0x6AC5C567`, image size `0x052D6000`). Static Probe **009B** rechecked all **39/39** incoming byte patterns and grouped them into **24** `.pdata` ranges; the three `game_time` sites lie in two ranges. These are not decoded functions or clock proof. **Owner-run offline Probe 009C–009E completed on 2026-10-12**: Capstone 5.0.6 decoded **39/39** expected RIP-relative LEA/string references across **24** unwind ranges by linear sweep; **17** ranges have undecoded E8-shaped caller candidates. These are genuine *linear-disassembled reference sites*, **not** proven entry-reachable instructions or playback-clock functions. Some label references may be UI/string/error handling. **Owner-run 009F–009H (2026-10-13, exact 0.6.3 static evidence):** 37/39 known LEA references were reachable in a bounded approximate entry CFG; both unreachable references had `seek` labels. 45 caller bytes decoded as direct `CALL` instructions, **not proof they execute**. Path-like `replay` and error-like `seek` contexts demoted generic keyword leads. **Owner-run 010A–010H (2026-10-13, 0.6.3 exact original EXE, static only):** 1,427 matching string occurrences; 383 instruction-decoded RIP-relative LEA xrefs, owned by 190 unwind intervals. The prior scanner capped full CFG analysis at 90 intervals (not all 190), and one `played_tick`, 22 `game_speed`, two `berserker_skill1` literal occurrences did not establish native time/buff semantics. 010G optional sound folder **not supplied**. **Owner-run 011A–011P (2026-10-13, same exact original EXE, static only):** all **190/190** previously selected unwind regions received approximate CFG review; **327/379** associated sources entry-reachable by that approximation. Crucially, two actual decoded **SIMD-memory** references to `berserker_skill1` exist at `0x019E62EC` (`movdqa`) and `0x02AD4674` (`movdqu`), neither found by the old LEA-only scan. One `game_speed` `pcmpeqb` reference exists, but native speed/clock semantics remain unproven. The full RIP sweep **truncated after 12,000,001 decoded instructions**, so absence of a `played_tick` RIP-reference is not exhaustive. A sound/path-named function statically calls a `game_time`-named function twice, potentially unrelated to replay. **Next source-only 012A–012T:** bigger decoder budget, caller neighborhoods, known-literal pointer/provenance checks; owner original-EXE run pending. Still required: semantically verified presentation-clock ownership, live pause/speed/rewind correlation and true Rage/death event ordering.
2. **Champion ability plumbing on native creeps:** native kind-3 minion attacks and genuine kind-15 Knight W have independently mapped paths to a shared native ready-effect executor (static 0.6.3 evidence). Genuine Knight W's correct state-5 progress is `entity+0x78`, with tagged target `+0x88..+0x9F`; earlier `+0xA0` attribution was rejected. Still unresolved: legitimate additional skill ownership/selection/cooldown on kind 3, effect-specific minion-origin validity, death/replay/cross-simulation consistency. See [native action research](../architecture/native-action-effects.md). Original champion W runtime behavior is not evidence of a creep casting W.
3. **Multiplayer authority and deterministic peer state:** verify vanilla two-client simulation equivalence, authority, and first divergence; then test whether tick-indexed external human inputs can affect the *live authoritative simulation*. This is separate from selecting free P2P/relay connectivity. [Cross-project multiplayer research](../architecture/multiplayer-authority-and-networking.md) · [Harbinger experiment plan](https://github.com/patrickehopkins/TFM2-DirectControl/blob/main/docs/multiplayer-research.md). **No input-injection or multiplayer compatibility claim.**
4. **Athlete lifecycle / identity stability:** census across season transitions, saves and reloads, transfers/retirement, stable IDs, roster minimum, forfeits and auto-recruitment. Dynasties probe plan (Dynasties source; private repository).
5. **General native-hook coexistence:** determine whether independent mods can safely hook the same version-gated entrypoint concurrently; isolated passes are not enough.
6. **Audio voice ownership (partially resolved):** TFM2 0.6.3 Berserker Probe **008** audibly confirmed **two F10-controlled in-process WinMM sequences** in which the lower voice stopped first and the upper voice continued, while the tester explicitly confirmed normal game audio was uninterrupted. Separate stop-request callbacks occurred at **2166/3891 ms** and **1756/3386 ms**. **Lifecycle follow-up verified (v0.0.8):** the eight-second watchdog audibly stopped both owned voices, and a separate active-voice InGame-to-Title transition logged cleanup and produced audible silence. **Quit-to-Windows was inconclusive** for clean unload; watched simulation diagnostics continued after title presentation cleanup. **Still open:** exact replay-timed Rage/death events, native game master/SFX gain linkage, pause/seek/speed, forced DLL unload/crash safety, multiple-Berserker lifetimes and XAudio2. Earlier results and the third-party **named Sfx → sound_info → clip/override** asset-registration route (static only, unknown runtime game version) are preserved in [audio research](../architecture/audio-and-frame-events.md). Next sound gate: independently test a mod-authored named synthetic clip on exact 0.6.3; asset registration is not interruptible voice ownership.
7. **Version migrations:** re-identify native addresses and field layouts for each new executable fingerprint, with runtime smoke tests.

For each resolved question: preserve the original implementation-specific report in its mod repository, publish the generalized result here, and explicitly mark what remains unproven.
