**Origin:** Creep Chaos Probes 010F, 010G-3, 010H, 010J, **corrective Probe 010K-4**, offline clone classification **010L-4**, **010M-1** static selector contrast, **010M-2** kind-dispatch verification, **010M-3** spatial-callee follow-up, **010N-1** caller topology, **010N-2** vector-handoff classification, **010N-3** upstream caller comparison, and **010N-4** post-builder cached-spec refresh, studied 2026-10-08 to 2026-10-10. Full traces and standalone verifiers remain in the originating mod repository. This summary does **not** establish executable champion skills on native creeps.

**Exact Windows build constraint:** Teamfight Manager 2 **0.6.3**, original game EXE SHA-256 `f21cf691799a83d9afa0ccae3e2b95862f5780446a501ee97860b91b752dbe2f`; PE timestamp `0x6AC5C567`; SizeOfImage `0x052D6000`. ## What has been established

The game has an original per-entity action representation, native cached refcounted effect specifications, and an **original 0x38-byte ready-effect vector** local to the simulation-state processor. Different entity kinds can generate records into that common final effect pipeline. The native callback is an effect-object virtual method **`vtable+0x20`** called in original simulation code at VA **`0x1416FB44F`**.

- **Ordinary native kind-3 lane-minion attack (STATIC):** its original action slot A (`entity+0x568/+0x570`) has an active-action/timing path which constructs a ready record from its cached slot-A effect spec (`entity+0x488`) at VA **`0x1416F8372–0x1416F83DA`**, via original append helper **`0x1416E8730`**. Its runtime action is a concrete `target_attack` type, but the melee action's vtable and effect callback are **not** identical to a champion's identically named attack. The ready records are processed through the same effect-object dispatcher as champion effects.
- **Original kind-15 champion Knight W (STATIC):** the accepted *deferred* W action-start route sets `entity+0x70=5`, initializes **progress `entity+0x78=0`**, and stores a native **24-byte tagged target at `entity+0x88..+0x9F`**. This target is prepared by original helper VA **`0x14140A6A0`**, which copies targets of tag other than 2 and may clamp position-tag 2 relative to caster coordinates and range.
- **Original champion W timed effect (STATIC):** kind-15 action state 5 selects slot C W at VA **`0x1416F7F68`**. The original W-specific branch **`0x1416F7FF6` unconditionally jumps to `0x1416FAEE3`**, where effect timing is calculated. The comparison at **`0x1416FAF0D`** uses **actual W progress `entity+0x78`**. On phase equality, the original effect is retained/refcounted, source identity `entity+0x5B8` and the target **from the same `+0x88..+0x9F` region** are packaged; VA **`0x1416FAF7A`** appends a genuine ready-effect record via `0x1416E8730` for original callback dispatch.
- **Original W progress and completion (STATIC):** the same native simulation-state function dispatches kind 15 again (kind update jump table RVA **`0x03BB40BC`**), and its state-5 update branch at VA **`0x1416FD3F1–0x1416FD3F8`** **increments `entity+0x78`**, compares against a native calculated completion duration and, on completion, reaches **`0x1416FD44D`** which resets action state 5 to 0. This is a **normal action-duration completion route**, not proof of death/cancellation semantics.
- **Conditional alternate scheduler (STATIC):** the original champion W action-entry method also contains a separate original condition-controlled path which can enqueue a refcounted effect in an entity-owned 0x38-byte **pending countdown queue** at `entity+0x2A0/+0x2A8/+0x2B0`. This **is not the only native W path**. The common effect processor can consume such records, including in kind-3 processing; that consumer reachability **does not prove a minion can legitimately produce W records**.
- **Original entity action and pending-effect lifetime (STATIC):** native entity cloning uses action-specific clone methods for five action slots and retains cached effects; a full entity clone duplicates pending effect records into independent queue storage with retained effect-object references. Common entity teardown releases those objects. A stored vtable address alone is therefore not a safe ability installer.

- **Additional full entity-array action-clone path (STATIC, Probe 010L-4; 2026-10-10):** offline disassembly from the exact-build-fingerprinted user scan shows native RVA **`0x01071BD0`** obtaining a source array pointer and multiplying a record count by **`0x6B8`**, reading source slot-C action data/vtable `+0x588/+0x590`, invoking the action's **vtable `+0x48` clone**, then copying the prepared C cached-effect/tag `+0x4F8/+0x528` and the cloned action pair to corresponding offsets in an **indexed destination record**. Nearby writes cover the rest of the native action set and other entity data. This clarifies an ambiguous 010L-3 “potential setter” as **another deep-clone/array assembly path, not a live kind-3 ability installer**. A local verifier checked **27/27 exported instruction/report anchors**, but the original EXE was not independently rescanned in the review environment and the caller/simulation-copy context is **unmapped**. Never infer that copying existing owned actions creates a new ability or authorizes minion use.

## Native entity constructor and action-cache caller topology — 010N-1 (2026-10-10)

The scanner recognizes **direct-immediate native calls only** and therefore cannot conclude anything from the absence of indirect/virtual factory calls.

- The original lane-minion constructor **RVA `0x013F9880`** has **12 direct call sites, all within caller RVA `0x013FAB90`**. Their three stack arguments cover the full observed **2 × 3 × 2** matrix: `[rsp+0x38]` ∈ {0,1}, `[rsp+0x28]` ∈ {0,1,2}, and `[rsp+0x20]` ∈ {0,1}. **Parameter game meaning is unknown.** Eight call sites immediately pass the resulting local record to **RVA `0x0140B6C0`**; the remaining four show nearby explicit **`0x6B8` entity-stride** collection assembly. - An authentic four-action champion constructor **RVA `0x0140A850`** has one direct caller (**RVA `0x01416410`**), a useful contrast with minion construction.
- The native default initializer **RVA `0x017263D0`** has **37** direct sites across **19** caller functions. The single-entity deep clone **RVA `0x0149CA90`** and cached-effect refresh **RVA `0x01701360`** each have **32** direct sites (12 and 11 unique caller functions respectively). **Six functions** (`0x013E1FA0`, `0x013E2980`, `0x013E54B0`, `0x013E8380`, `0x013EA0F0`, `0x013FF300`) contain **both clone and refresh calls**, often with comparable counts. In the `0x013E8380` caller, paired clone/refresh sites are separated by only a few instructions; **same-object ownership, real execution order across branches, and authoritative copy/fan-out are unproved**.
- Full entity-array clone **RVA `0x01071BD0`** has two direct calls from **RVA `0x0148C220`**, which also directly calls a single-record clone. Treat this as a **simulation-copy investigation lead**, not proof that it duplicates workers or accepts new action definitions.

Static direct-call co-occurrence is neither a live ability-slot setter nor proof of a deterministic simulation-insertion boundary; verify exact object provenance, lifecycle and worker copies before writing anything. The proposed follow-up is a bounded read-only analysis of **RVA `0x0140B6C0`** and the twelve-way caller alongside a known champion constructor and clone/refresh control. ## Native minion record handoff — 010N-2 (2026-10-10)

**STATIC, user-executed read-only original-build-gated report; no runtime authorization.** TFM2 **0.6.3 Win64**, reported exact original EXE SHA-256 `f21cf691799a83d9afa0ccae3e2b95862f5780446a501ee97860b91b752dbe2f`, PE timestamp `0x6AC5C567`, SizeOfImage `0x052D6000`. Creep Chaos `probe010n2-handoff.json` decoded **26/26 native instructions** at helper RVA **`0x0140B6C0..0x0140B716`**; its entire function is represented in the selected report, unlike larger function excerpts. **54/54 local JSON/report-level metadata and bounded instruction checks** passed; the original EXE was **not independently re-scanned** here.

**Resolved:** The original helper **`0x0140B6C0`** invoked after native minion constructor is **a fixed-size vector append, not an action installer**. It reads length at collection `+0x10` and capacity at `+0x0`, calls a grow helper at RVA `0x039405F0` when needed, calculates destination `base(+0x8) + length × 0x6B8`, then calls RVA `0x0387FD09` with source, destination and `0x6B8` bytes (a **bulk-copy-like routine by its usage**, not separately classified from its full body). The append increments collection length. It neither directly constructs/independently clones action objects nor refreshes cached effects. No verified B/C/D ability injection or owned action setter exists here.

The original minion builder **RVA `0x013FAB90`** has 12 compiled constructor sites for the three-argument **2×3×2** matrix. Eight use the above append helper; four perform **equivalent-looking inlined `0x6B8`-stride bulk-appends**, converging on a common vector header/output. The precise meanings of the constructor arguments and final consumer/authority of this vector **remain unproven**. A bulk copy of an entity containing native action pointers is **not** an action-specific deep clone, and its ownership/move/destruction semantics cannot be inferred from the copy alone.

**Distinct positive control:** A separate native original path (RVA **`0x013E8380`**) contains a proven **same-temporary sequence**: single-entity deep clone **`0x0149CA90`** into `[rbp-0x60]`, cache-spec refresh **`0x01701360`** on that temporary, **`0x6B8` bulk copy** out to another record, and a call to downstream `0x013FB4B0`. This demonstrates why **copying an already properly cloned/refresh-owned record** is a different operation from **creating a newly owned ability**. The sequence is not evidence that lane minions or simulation workers use this exact chain.

**Generalizable limitation:** A native vector insertion point is not automatically a safe native action installation or authoritative simulation hook. Verify original action factory type, refcount/clone/drop semantics, collection move/reallocation, and actor-kind state dispatch separately. Next original Creep Chaos research is **010N-3 read-only upstream direct callers of the minion builder/append helper** (prepared, not executed). Indirect or inlined paths, authoritative worker replication and native kind-3 champion skill scheduling remain unproven. Original project document: `docs/PROBE-010N2-MINION-VECTOR-HANDOFF-FINDINGS.md`; no full report, raw disassembly dump, local paths or proprietary binary in public KB.
