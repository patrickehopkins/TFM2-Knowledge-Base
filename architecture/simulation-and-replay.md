# Simulation and visible replay are separate

**Status: runtime verified** across independently instrumented Harbinger, Flame Simulator and Berserker projects; exact mechanisms vary by build. Sources: [Harbinger simulation](https://github.com/patrickehopkins/TFM2-DirectControl/blob/main/docs/simulation-research.md), Flame rewind (Flame Simulator source; private repository), Berserker Probe 002 (Berserker Keeps Yelling source; private repository).

A watched match's client simulation can finish far ahead of the on-screen playback clock. An AI callback tick **must not** be used as a direct presentation timestamp or wall-clock audio trigger.

## Concrete evidence

- Harbinger observed simulation/AI callbacks stop while the visible clock continued. A visual-clock-matched `StablePlayerAi` return did not produce authoritative interactive control. The old `match_view +0x250/+0x258` display-clock hypothesis was physically rejected.
- Flame 0.6.1 Probe 0.2.0 observed two deliberate rewinds from 00:06 and 00:05 to 00:00 while the sampled simulation stream continued forward; visible chat text remained immediately after seeks. First readable opening text occurred at displayed 00:02 on multiple passes but differed in wording. The *first readable poll* is not an exact native spawn instant.
- Berserker 0.6.3 Probe 002 observed Candidate-A tick `36,471` (~10:07.85 at 60 tps) by visible HUD **00:47**; the rendered match continued to **10:07** while the watched simulation's tick had stopped increasing.

## Probe 009A: static replay/HUD anchor reconnaissance (not a clock)

**Static evidence, not runtime validation; exact TFM2 0.6.3 executable (2026-10-11):** An offline original-EXE scan from Berserker Keeps Yelling Probe 009A recorded SHA-256 `f21cf691799a83d9afa0ccae3e2b95862f5780446a501ee97860b91b752dbe2f`, PE timestamp `0x6AC5C567`, image size `0x052D6000`. The scanner found **4** `game_time` substring occurrences and **3** possible RIP-relative LEA-shaped source references (RVAs `0x009106D4`, `0x00B9D243`, `0x00B9D3BA`). It also found 43 `replay` and 41 `seek` occurrences, but **retained only the first 24 per token**, so those sets were truncated. Other exact tokens—including `ingame.header`, `current_frame` and `frame_index`—had zero string matches.

These are **limited string/byte-pattern matches**, not disassembled or instruction-boundary-verified references, time-update functions, playback counters, or safe hook sites. The lack of a literal UI string does not imply its UI node or semantic behavior is absent. **Probe 009B was subsequently run on that exact EXE (static evidence, 2026-10-12):** all **39/39** incoming LEA-shaped byte patterns matched again, with zero pattern rejects, and **154,191** PE `.pdata` unwind ranges were indexed. Those references grouped into **24 candidate function ranges** (none dropped at the function-group stage). The three `game_time` sites belong to **two** unwind ranges: `0x00B9C970–0x00BBDB54` (two sites) and `0x0090EB40–0x00916EC9` (one). **No instruction boundaries, native playback cursor, function semantics or hook safety have been proved.** The initial `replay`/`seek` string lists remain truncated. **Probe 009C–009E completed on the owner's exact 0.6.3 EXE (offline static evidence, 2026-10-12):** With **Capstone 5.0.6**, all **39/39** sites from the 24 unwind ranges were decoded as RIP-relative `lea` instructions whose targets matched the 009A/009B labels in a **linear sweep from their unwind starts**. No sites were unreachable to the *linear decoder*. **17** ranges had one or more **undecoded `E8`-shaped possible caller sites**; these remain hypotheses until proper caller instruction-boundary verification.

This is an improvement from raw byte matching, but **still not a validated playback-clock function or reliable runtime event source**. Several apparent `replay` and `game_time` references sit near generic text assembly/lookups; one `playback` reference is next to a potential unreachable/error handler ending in `ud2`. These are **static semantic hypotheses**, not confirmed identities. **Owner-run Probe 009F–009H (offline static, 2026-10-13):** on that exact 0.6.3 fingerprint, **37/39** decoded string-reference sites were reachable in a bounded approximate CFG from their unwind-region beginnings; the two non-reachable sites had `seek` labels. **45** caller-shaped bytes were independently decoded into direct `CALL` instructions, but no call *execution* or semantic replay ownership is established. Several `replay` references occurred within path-like string contexts and `seek` references within error-like contexts, reducing their usefulness as timer indicators. The old Harbinger +0x250 played-tick candidate remains rejected. **Owner-run 010A–010H (2026-10-13, exact 0.6.3 original EXE, offline static):** **1,427** string-token occurrences in nonexecutable sections, **383** Capstone-decoded RIP-relative LEA reference candidates across **190** native unwind groups; prior scanner retained only **90** groups for detailed CFG checks (explicit truncation). One `played_tick` string, 22 `game_speed` and two `berserker_skill1` occurrences are useful specific *literal leads*, but **no direct candidate LEA source carried a `frame_clock` or `time_control` label**, and no Rage event was proved. An independent optional sound-mod folder audit was not supplied. One sound-named group at `0x00930640` statically calls a `game_time`-named group at `0x00B9C970` twice; **shared loading/serialization is a plausible alternative**, not an audio-playback-clock proof. **Owner-run 012A–012T (2026-10-13, same original 0.6.3 EXE; static):** `full_linear_scan` finished **60,591,616 executable-section bytes / 14,506,755 decoded instructions**, no skipped section bytes or truncated reported references. ## Watcher versus authority

Creep Chaos Probe 002 physically revalidated watched ClientMatchView Candidate A on its exact 0.6.3 build, but explicitly does **not** treat it as the authoritative simulation mutation surface. The stable `StableMatchHook` handles deterministic game-rule mutations; a watched-client/native hook is for observation or presentation. The engine can maintain more than one simulation context.

## Playback speed is a renderer-sampling condition, not a simulation clock

**RUNTIME VERIFIED METHODOLOGY CORRECTION (Creep Chaos v0.0.29, original TFM2 0.6.3, SDK ABI9, 2026-10-13):** a user-executed watched match was viewed at a reported constant **3× playback speed** while a probe independently observed the watched simulation stream and exact native primary-renderer callbacks. The first **2,048 / 2,048** watched renderer callbacks still shared the same exact primary return path and one unanimous raw stack depth. A bounded one-frame extension then verified **5,584** more exact-primary callbacks before one mismatch triggered its fail-closed stop. The same run's renderer-local cohort summary still contained only the first complete `melee → melee → ranged` visible cohort candidate, while the independent SDK conceptual spawn schedule had already recorded complete phases through multiple later wave candidates. No shared clock was inferred.

This does **not** establish that 3× caused the later stack mismatch. It establishes a more general testing rule: **visible playback speed is an experimental condition for renderer/presentation probes.** Increasing replay speed can change how much game time advances between rendered frames/callbacks and therefore can change callback density, per-callback movement and how much visible playback a bounded callback window covers. Conversely, simulation ticks and already-observed simulation-side spawn semantics are not reinterpreted merely because the user changes replay speed.

For renderer-sensitive experiments, record playback speed, use a fixed-speed baseline (preferably 1×), and do not change speed, seek, pause or leave for match results before the required visible-coverage condition is met. Treat exact callback-ordinal gaps and per-callback geometric thresholds as playback-regime-dependent calibration data until verified across speeds. A later accelerated-speed run is a compatibility/stress test, not a substitute for a controlled baseline.

## Practical consequences

- Keep simulation tick, presentation clock, wall clock, scene epoch, and instance identity as **separate fields**.
- Replay rewind must not replay irreversible persistent career mutations, simply because the visible clock moved backward.
- For audio, investigate frame-recorded sound events; do not trigger client sound directly from a presimulation callback.
- For multiplayer, first prove vanilla peer state equivalence before injecting externally synchronized inputs.

## Not yet proved

These observations do **not** disclose a sample-accurate presentation clock, unique cross-match ID, general determinism of repeated fresh matches, or the exact native chat event queue. Do not infer those capabilities from a few matched timestamps.


## Coarse HUD-time mapping under playback acceleration: Berserker 013 (2026-10-13)

**Physically observed partial result:** TFM2 **0.6.3**, host/stable SDK **ABI 9**, Berserker **v0.0.9** used an approximate **HUD integer seconds × 60 simulated ticks** mapping to start/stop independent synthetic voices from *already presimulated* `berserker_skill1` transitions. **16 starts, 15 natural ends and one pause cleanup** were logged in a visibly playing match; owner confirmed the sound was late compared with the first cast animation frame and ceased after red visual state ended. The same HUD polling path skipped multiple integer game seconds during accelerated playback (e.g. **01:07 → 01:10 → 01:14 → 01:18** between samples). Thus **integer HUD polling cannot guarantee detecting a full short-lived ability interval at high replay speed**, even though the source simulation log contains all 179-tick intervals.

**Boundary:** this is a limitation of the **diagnostic's mapping and sampling**, not a proof about which native replay field is authoritative. Faster polling, fractional interpolation and a calibrated lead (Berserker **014**, CI synthetic only as of 2026-10-13) may improve audible alignment but cannot replace a genuinely measured visible playback clock or event queue. The **beginning of a cast animation**, effect/buff activation, visual color changes, and expiration may be independent temporal landmarks; verify each. Pause/resume state machines should **suspend** owned audio while maintaining eligibility to resume, rather than interpreting a short HUD stall as an irreversible session termination. Ensure duplicate/missing events, match epoch, seek, and pitch per entity ID are tested separately.
